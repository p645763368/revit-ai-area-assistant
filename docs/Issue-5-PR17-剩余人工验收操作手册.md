# PR #17 / Issue #5 剩余人工验收操作手册

> 本手册中的五项验收已于 2026-08-14 执行完成并全部通过，结果见[《PR #17 / Issue #5 人工验收记录（2026-08-14）》](Issue-5-PR17-人工验收记录-2026-08-14.md)。本文继续保留，供后续复测使用。

## 1. 这份手册解决什么问题

这份手册只用于完成 PR #17 目前尚缺少的 Revit 2026 真机证据。面向不懂代码的测试人员；你不需要使用 Git、Python、PowerShell，也不需要编辑 JSON 文件。

需要完成的人工验收共有四组：

1. 在同一个 Revit 进程中，从文档 A 切换到文档 B 后，旧会话必须立即暂停；
2. 文档 A 的 AI 回复仍在途中时切换到 B，迟到回复不得写入 A 的外部记录；
3. 旧会话撤销失败时必须保持暂停，不能继续验证或打开 B；点击“验证文档”重试成功后才能继续；
4. 整个测试前后 RVT 文件的磁盘修改时间必须不变，证明插件没有自动保存模型。

本测试不创建 Area、Boundary、Tag、明细表，也不执行任何 Revit 模型写入。

## 2. 测试人员只需要认识这些界面

AI Area Assistant 面板从上到下有以下区域：

| 面板区域 | 你会看到什么 | 本测试中的用途 |
|---|---|---|
| 连接状态 | “连接中”“已连接”“切换暂停”等 | 判断 Agent 是否可用 |
| 文档安全状态 | “验证文档”按钮、状态和当前文档信息 | 重新验证当前文档 |
| 会话状态 | “继续上次会话”“新建会话”按钮 | 为当前文档明确选择会话 |
| 对话区 | “你：”和“AI：” | 查看回复是否继续出现 |
| 输入框 | 输入测试消息 | 只输入本手册提供的匿名文字 |
| 重试 / 发送 | 两个按钮 | 重试聊天或发送消息 |

请特别区分：

- “重试”按钮用于重试聊天请求；
- “验证文档”按钮用于重新验证文档，也用于重试失败的旧会话撤销；
- 文档切换失败时，本手册要求点击的是“验证文档”，不是“重试”。

## 7. 用例 1：建立文档 A 基线并确认显式选择

### 操作步骤

1. 启动 Revit 2026。
2. 只打开文档 A。
3. 打开 `AI Area Assistant` 选项卡，点击 `AI Area Assistant`。
4. 等待最多 60 秒。
5. 确认“连接状态”最终为“已连接”。
6. 等待“文档安全状态”完成验证。验证中不要修改或切换文档。
7. 查看“会话状态”：
   - 如果存在旧会话，应显示“发现上次会话，请选择继续或新建会话”；
   - 如果没有旧会话，应显示“当前文档没有上次会话，请选择新建会话”。
8. 在没有选择前确认“发送”按钮不可用。
9. 点击“新建会话”。
10. 等待“会话状态”显示“新会话已建立，等待你的操作”。
11. 确认“发送”按钮可用，“新建会话”按钮变为不可用。
12. 输入：`人工验收 A 基线：请只回复“A基线完成”。`
13. 点击“发送”，等待回复完成。
14. 打开文档 A 的外部数据目录，找到刚刚更新的会话目录。
15. 记录 `conversation.jsonl` 的文件大小和修改时间。

### 通过标准

- [ ] 用户选择前不能发送；
- [ ] 必须由用户点击“继续上次会话”或“新建会话”；
- [ ] 新会话激活后不能再次点击“新建会话”；
- [ ] A 的消息写入 A 的外部目录；
- [ ] 没有自动执行 Revit 操作。

任一项不符合，停止测试并记为失败。

## 8. 用例 2：同一 Revit 进程中从 A 切换到 B

### 操作步骤

1. 保持 Revit 和文档 A 打开，不退出 Revit。
2. 使用 Revit 的“打开”命令打开文档 B。
3. 确认 A 和 B 同时在同一个 Revit 进程中打开。
4. 点击 B 的视图或窗口，使 B 成为当前活动文档。
5. 立即观察 AI Area Assistant 面板。
6. 必须立刻看到：
   - “发送”按钮不可用；
   - “继续上次会话”和“新建会话”按钮暂时不可用；
   - 会话状态出现“文档已切换；旧会话已暂停，正在读取新文档”。
7. 等待最多 60 秒，不点击“发送”或“重试”。
8. 验证完成后，面板必须要求为 B 选择会话。
9. 在选择前确认“发送”仍不可用。
10. 查看会话状态显示的数据目录，必须是 B 的目录，不能仍是 A 的目录。
11. 点击“新建会话”。
12. 输入：`人工验收 B：请只回复“B会话完成”。`
13. 点击“发送”，等待回复完成。
14. 检查 B 的外部数据目录，确认出现 B 的消息。
15. 检查 A 的 `conversation.jsonl`，确认没有“人工验收 B”文字。

### 通过标准

- [ ] 切到 B 时 A 会话立即暂停；
- [ ] B 验证完成前不能发送；
- [ ] B 必须重新要求用户选择会话；
- [ ] B 消息只进入 B 的外部目录；
- [ ] A 的外部记录没有 B 的内容。

如果切到 B 后仍能发送，或仍显示 A 的数据目录，立即停止并判定失败。

## 9. 用例 3：A 的回复仍在途中时切换到 B

这个用例验证“迟到回复不能写进旧文档目录”。

### 准备

1. 完全退出 Revit；如询问保存，选择“不保存”。
2. 重新启动 Revit，只打开 A。
3. 打开面板并等待文档验证完成。
4. 选择“继续上次会话”或“新建会话”。
5. 打开 A 当前会话目录，记录 `conversation.jsonl` 的文件大小和修改时间。
6. 在 Revit 中同时打开 B，但保持 A 为当前活动文档。

### 操作步骤

1. 在 A 的面板中输入：
   `迟到回复测试：请分五段说明春夏秋冬和雨季，每段单独输出。`
2. 点击“发送”。
3. 等到对话区出现第一段 AI 文字，但状态仍为“回答中”。
4. 立即切换到 B。
5. 确认“发送”马上不可用，并看到旧会话暂停提示。
6. 等待 60 秒，让旧请求有足够时间返回。
7. 不要为 B 选择会话。
8. 刷新 A 会话目录。
9. 打开 A 的 `conversation.jsonl`，检查是否出现完整的五段迟到 assistant 回复。
10. 记录切换前后文件大小和修改时间。

### 通过标准

- [ ] 切到 B 后，A 的迟到回复不会继续显示为 B 的回复；
- [ ] A 的 `conversation.jsonl` 不新增切换后完成的 assistant 消息；
- [ ] B 未选择会话前没有创建或写入 B 会话；
- [ ] 面板保持暂停或等待 B 的明确选择。

说明：切换前已经成功写入的用户消息可以存在；本用例关注的是切换后才完成的旧 assistant 回复不得落盘。

## 10. 用例 4：旧会话撤销失败时必须保持暂停并可重试

这个用例需要一名开发人员协助制造一次可恢复的 Agent 通信失败。测试人员不要自行结束进程、改防火墙或修改环境变量。

### 开发人员准备

开发人员应使用安全、可恢复的方法，让下一次 `session.revoke` 请求失败一次，随后恢复正常。不得修改 RVT，不得使用真实敏感数据。准备完成后只告诉测试人员“可以开始切换”，不要让测试人员操作开发工具。

### 测试人员操作

1. 完全重启 Revit，打开 A，打开面板并激活 A 会话。
2. 确认“发送”按钮可用。
3. 请开发人员确认下一次撤销会失败。
4. 在同一 Revit 进程中打开并切换到 B。
5. 等待最多 60 秒。
6. 必须看到：
   - 连接状态为“切换暂停”；
   - 会话状态包含“旧会话撤销失败；保持暂停”；
   - 说明文字包含“不会验证或打开新文档会话”；
   - “发送”“继续上次会话”“新建会话”均不可用；
   - “验证文档”可用。
7. 此时不要点击“重试”，也不要发送消息。
8. 再在 A 和 B 之间切换一次，确认面板仍保持上述暂停状态，不能绕过屏障。
9. 请开发人员恢复 Agent 通信，并确认可以重试。
10. 点击一次“验证文档”。
11. 不要连续点击，等待最多 60 秒。
12. 撤销成功后才应开始验证 B。
13. 验证完成后，面板应要求为 B 选择“继续上次会话”或“新建会话”。
14. 在选择前确认“发送”仍不可用。

### 通过标准

- [ ] 撤销失败后没有验证或打开 B 会话；
- [ ] 所有会话操作保持禁用；
- [ ] 继续切换文档不能绕过暂停；
- [ ] 错误提示明确告诉用户点击“验证文档”重试；
- [ ] 一次显式重试成功后才验证 B；
- [ ] 没有自动恢复 A，也没有自动为 B 建立会话。

如果撤销失败后 B 仍进入会话选择或“发送”变为可用，判定为安全阻断失败。

## 11. 用例 5：确认 RVT 没有自动保存

1. 完成以上测试后，不要在 Revit 中点击保存。
2. 保持 Revit 打开，在文件资源管理器中查看 A 和 B 的“修改时间”。
3. 记录为“A 关闭前修改时间”和“B 关闭前修改时间”。
4. 关闭 A；如果询问是否保存，选择“不保存”。
5. 关闭 B；如果询问是否保存，选择“不保存”。
6. 完全退出 Revit。
7. 再次查看 A 和 B 文件属性中的“修改时间”。
8. 记录为“A 测试后修改时间”和“B 测试后修改时间”。
9. 分别与第 6 节记录的测试前修改时间逐字比较。

### 通过标准

- [ ] A 测试前与测试后修改时间完全一致；
- [ ] B 测试前与测试后修改时间完全一致；
- [ ] 所有新记录只出现在 `AI_Area_Assistant_Data`；
- [ ] 测试人员没有保存任何 RVT。

如果任一 RVT 的修改时间发生变化，不要再次打开或保存它。记录时间差异并把本用例判定为失败。

## 13. 失败时如何处理

1. 停止点击面板，不要尝试自行修复。
2. 不保存 A 或 B。
3. 记录失败用例、步骤编号、发生时间和面板原文。
4. 记录哪些按钮可用、哪些按钮不可用。
5. 只记录外部文件名、大小和修改时间，不上传文件内容。
6. 将结果标为“失败”；环境不满足时标为“阻塞”。
7. 把匿名化的测试摘要交给开发人员。

以下任一现象都属于必须停止的安全失败：

- 切换文档后“发送”仍可用；
- B 的消息写入 A 的目录；
- A 的迟到 assistant 回复在撤销完成后仍落盘；
- revoke 失败后仍验证或打开 B 会话；
- 用户没有选择却自动恢复或新建会话；
- RVT 修改时间发生变化；
- 出现任何未授权的 Revit 模型操作。
