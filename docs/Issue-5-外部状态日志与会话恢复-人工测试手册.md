# Issue #5 外部状态、日志与会话恢复人工测试手册

## 1. 这份手册适合谁

这份手册面向没有软件开发经验的测试人员。你不需要会写代码，也不需要理解Git、Python或JSON。

请严格按顺序操作。每完成一个步骤，就在对应检查框中打勾。如果实际画面与“预期结果”不同，请停止当前用例，记录失败现象，不要自行删除文件或反复点击按钮。

本轮测试只检查：

- 会话状态是否保存到Revit模型以外的本地目录；
- 关闭并重新打开面板后，是否让用户选择继续旧会话或新建会话；
- 不同Revit文档的会话是否相互隔离；
- 对话、工具操作和错误是否同时具有机器可读记录和人工可读记录；
- 敏感字段是否被遮蔽；
- 恢复会话时是否不会自动继续旧的模型操作；
- 测试过程是否不会修改或自动保存RVT。

本轮不测试Area Plan、Area Boundary、Area、Tag、面积表或任何Revit模型写入。

---

## 2. 最重要的安全规则

开始前请确认以下每一项：

- [ ] 只打开项目负责人指定的开发测试副本，例如：`项目名_开发测试副本_detached.rvt`。
- [ ] 不打开或测试原始项目模型。
- [ ] 不在面板中输入真实API密钥、真实Authorization内容、业主信息或其他敏感数据。
- [ ] 不把RVT、运行日志、数据目录或项目截图提交到GitHub。
- [ ] 如果需要截图，只保存在测试电脑的临时证据目录，并确认截图中没有密钥或真实项目敏感信息。
- [ ] 测试结束时不保存RVT；如果Revit询问是否保存，选择“不保存”。
- [ ] 不手工删除或改写`AI_Area_Assistant_Data`中的文件，除非开发人员明确要求重置测试。

如果你不确定当前打开的是不是开发测试副本，立即停止测试并询问项目负责人。

## 5. 配置并打开测试环境

### 5.1 确认Windows环境变量

如果开发人员已经配置完成，测试人员只需确认，不要查看或复制真实密钥的内容。

1. 按Windows键。
2. 输入“环境变量”。
3. 点击“编辑账户的环境变量”。
4. 在“用户变量”区域确认存在以下变量名：
   - `AI_AREA_ASSISTANT_API_KEY`
   - `AI_AREA_ASSISTANT_MODEL`
   - `AI_AREA_ASSISTANT_BASE_URL`
5. 只确认变量名存在，不展开、不复制、不截图变量值。
6. 如果变量缺失，关闭窗口并通知开发人员，不要把密钥写进脚本、文档或聊天消息。

### 5.2 启动Revit和pyRevit扩展

1. 完全关闭所有Revit窗口。
2. 重新启动Autodesk Revit 2026。
3. 等待pyRevit加载完成。
4. 打开开发人员提供的开发测试副本。
5. 核对Revit标题栏中的文件名必须包含：`开发测试副本_detached`。
6. 不进行墙、楼板、房间、面积或参数编辑。
7. 在Revit功能区找到`AI Area Assistant`选项卡。
8. 点击`AI Area Assistant`按钮。
9. 预期Revit右侧出现“AI Area Assistant”面板。

如果找不到选项卡或按钮，请先让开发人员核对pyRevit扩展目录，不要继续后面的用例。

## 6. 用例00：确认Issue #5是否真的接入面板

### 操作步骤

1. 打开AI Area Assistant面板。
2. 等待最多60秒。
3. 观察面板是否先显示“连接中”，随后显示“已连接”。
4. 查看面板中是否出现与会话有关的提示或入口，例如：
   - “继续上次会话”；
   - “新建会话”；
   - 当前会话编号；
   - 会话恢复提示。
5. 如果这是第一次使用且没有旧会话，面板可以直接创建新会话；此时继续执行第6步。
6. 请开发人员提供`AI_Area_Assistant_Data`预计完整路径。
7. 用文件资源管理器打开该路径。
8. 在面板中发送一条匿名测试消息：`请只回复：Issue 5 会话测试成功。`
9. 等待AI回复完成。
10. 返回文件资源管理器并按`F5`刷新。
11. 检查数据目录中是否出现`documents`文件夹和新的会话文件。

### 预期结果

- [ ] 面板可以连接到本地Agent。
- [ ] 面板发送消息后，`AI_Area_Assistant_Data`中出现或更新会话文件。
- [ ] 至少能找到`state.json`、`conversation.jsonl`和`session.md`。

### 阻塞判定

出现以下任一情况，本用例记为“阻塞”，停止后续Issue #5面板测试：

- 面板只有聊天功能，发送消息后完全没有创建`AI_Area_Assistant_Data`；
- 面板代码或测试构建尚未接入Issue #5；
- 开发人员无法提供数据目录位置；
- 测试构建没有文档指纹来源；
- 面板无法连接本地Agent。

记录文字：

```text
Issue #5人工测试阻塞：面板可用，但未观察到会话持久化或恢复入口。
当前测试构建：
当前Commit：
面板可见控件：
发送消息后数据目录变化：
```

## 7. 用例01：新会话是否生成机器记录和人工记录

### 操作步骤

1. 确认面板状态为“已连接”。
2. 如果面板询问“继续上次会话”或“新建会话”，点击“新建会话”。
3. 在`测试记录.txt`中记下当前时间，作为会话A的开始时间。
4. 在面板输入以下消息：`会话A：请只回复“新会话记录成功”。`
5. 点击“发送”。
6. 等待状态从“回答中”恢复为“已连接”。
7. 确认对话区同时显示“你：”和“AI：”内容。
8. 打开开发人员提供的`AI_Area_Assistant_Data`完整路径。
9. 依次打开`documents`、当前文档目录、`sessions`。
10. 找到“修改日期”最接近当前时间的会话文件夹。
11. 在`测试记录.txt`中抄写该会话文件夹名称，这就是会话A编号。
12. 确认会话文件夹中至少包含：
    - `state.json`
    - `conversation.jsonl`
    - `session.md`
13. 用Windows记事本打开`state.json`。
14. 确认可以看到会话编号、状态、更新时间和文档指纹字段。
15. 用记事本打开`conversation.jsonl`。
16. 确认可以找到“会话A”测试消息和AI回复记录。
17. 用记事本打开`session.md`。
18. 确认内容比JSON更容易阅读，并包含会话标题、用户消息和AI消息。

### 预期结果

- [ ] 机器状态保存在`state.json`。
- [ ] 对话机器记录保存在`conversation.jsonl`。
- [ ] 人工可读记录保存在`session.md`。
- [ ] 三个文件属于同一个会话A目录。
- [ ] 文件中没有真实API密钥或Authorization值。
- [ ] Revit模型没有被修改或自动保存。

## 8. 用例02：重新打开后必须由用户选择，不能自动继续操作

### 操作前记录

1. 在文件资源管理器中查看会话A目录。
2. 如果存在`operations.jsonl`，记录它的“修改日期”和文件大小。
3. 如果不存在，记录“恢复前没有operations.jsonl”。
4. 记录面板中最后一条AI回复。

### 操作步骤

1. 关闭AI Area Assistant面板。
2. 等待10秒。
3. 再次点击Revit功能区中的`AI Area Assistant`按钮。
4. 等待面板连接完成。
5. 在没有点击任何会话选项、没有发送消息的情况下等待30秒。
6. 观察面板是否自动出现新的AI回复、自动进入“回答中”或自动执行工具。
7. 检查`operations.jsonl`的修改日期和大小是否发生变化。
8. 确认面板显示“继续上次会话”和“新建会话”供用户选择。
9. 点击“继续上次会话”。
10. 再等待30秒，不发送任何消息。
11. 再次确认没有新AI回复、没有自动工具操作。
12. 打开会话A的`state.json`。
13. 确认状态为`awaiting_user_action`，并确认`model_operation_pending`为`false`。
14. 现在发送：`会话A继续：请只回复“恢复后由用户触发”。`
15. 等待AI回复完成。
16. 刷新会话A目录，确认仍更新同一个会话A，而不是静默创建另一个会话。

### 预期结果

- [ ] 重新打开面板后必须先让用户选择。
- [ ] 用户选择前不自动继续任何旧任务。
- [ ] 点击继续后仍然等待新的用户操作。
- [ ] 只有点击“发送”后才产生新回复或新操作记录。
- [ ] `state.json`明确表示没有待执行模型操作。

以下情况必须判定失败：

- 面板打开后自动发送消息；
- 面板自动调用工具；
- 面板自动继续上次失败的请求；
- 用户未点击继续时就恢复并执行任务；
- 恢复过程中出现任何Revit写入或自动保存。

## 9. 用例03：新建会话不能覆盖旧会话

### 操作步骤

1. 记录会话A文件夹名称和最后修改时间。
2. 关闭并重新打开AI Area Assistant面板。
3. 在会话选择中点击“新建会话”。
4. 输入：`会话B：请只回复“新会话B成功”。`
5. 点击“发送”并等待回复完成。
6. 刷新`AI_Area_Assistant_Data`目录。
7. 检查当前文档的`sessions`目录中是否新增了另一个会话文件夹。
8. 记录新文件夹名称，作为会话B编号。
9. 确认会话B编号与会话A编号不同。
10. 打开会话A的`session.md`，确认原有内容仍存在。
11. 打开会话B的`session.md`，确认其中有“会话B”消息，但不应把会话A内容混入新会话。

### 预期结果

- [ ] 会话A仍然存在且内容未被覆盖。
- [ ] 会话B使用新的会话编号和独立目录。
- [ ] 会话B的人类记录只包含会话B内容。
- [ ] 用户可以在重新打开时选择继续旧会话或新建会话。

## 10. 用例04：不同文档指纹的数据必须隔离

只有开发人员确认“文档指纹功能已接入”后才能执行本用例。

### 准备第二个安全文档

第二个文档也必须是开发测试副本或专门创建的空白测试文档。禁止使用正式项目原模型。

### 操作步骤

1. 记录当前文档对应的`documents`子目录名称，称为“文档A目录”。
2. 关闭当前开发测试副本，不保存。
3. 打开开发人员批准的第二个测试文档。
4. 打开AI Area Assistant面板。
5. 观察恢复候选列表。
6. 确认列表中没有会话A和会话B。
7. 在第二个测试文档中点击“新建会话”。
8. 发送：`文档B隔离测试：请只回复“文档B成功”。`
9. 等待回复完成。
10. 刷新`AI_Area_Assistant_Data/documents`。
11. 确认出现另一个与“文档A目录”不同的文档目录。
12. 打开新文档目录中的`session.md`，确认只包含文档B消息。
13. 关闭第二个文档，不保存。
14. 重新打开原开发测试副本。
15. 打开面板，确认可以看到会话A/会话B，但看不到文档B会话。

### 预期结果

- [ ] 不同文档使用不同的文档目录键。
- [ ] 文档B不能恢复文档A的会话。
- [ ] 返回文档A后不能看到文档B的会话。
- [ ] 两个文档都没有被保存。

如果第二个文档能看到第一个文档的会话，本用例失败并停止后续测试。这是数据路由安全问题。

## 11. 用例05：敏感字段必须被遮蔽

本用例只使用以下虚构测试值。绝对不要使用真实密钥。

```text
Authorization: Bearer FAKE_TEST
api_key=FAKE_TEST
password=FAKE_TEST
session_token=FAKE_TEST
```

### 操作步骤

1. 回到开发测试副本的当前会话。
2. 在面板输入：`脱敏测试：Authorization: Bearer FAKE_TEST api_key=FAKE_TEST password=FAKE_TEST session_token=FAKE_TEST`。
3. 点击“发送”并等待回复完成。
4. 打开当前会话的`conversation.jsonl`。
5. 搜索`FAKE_TEST`。
6. 打开当前会话的`session.md`。
7. 搜索`FAKE_TEST`。
8. 如果存在`operations.jsonl`和`agent.log.jsonl`，也分别搜索`FAKE_TEST`。
9. 查找是否出现`[REDACTED]`。
10. 同时确认普通非敏感字段仍然可读，没有把所有内容都删掉。

### 预期结果

- [ ] 所有持久化文件中都找不到`FAKE_TEST`原值。
- [ ] 敏感值位置显示`[REDACTED]`。
- [ ] 普通对话文字、工具名、时间和非敏感结果仍然存在。

只要任一文件保留`FAKE_TEST`原值，本用例判定失败。不要把失败文件上传GitHub；只在测试记录中说明文件名和字段类型。

## 12. 用例06：工具调用、成功结果和错误是否可审计

如果当前面板还没有触发工具调用的入口，请把本用例记录为“暂不可执行”，不要伪造结果。

### 成功操作记录

1. 按开发人员提供的安全方式触发一个只读工具操作。
2. 不允许触发Area、Boundary、Tag或其他Revit写入。
3. 等待操作成功。
4. 打开当前会话的`operations.jsonl`。
5. 确认能看到工具名称、输入、输出、结果类型和时间。
6. 打开`agent.log.jsonl`，确认能找到对应工具事件。
7. 打开`session.md`，确认可以用普通文字阅读工具名称、输入和输出。

### 错误操作记录

1. 只使用开发人员批准的安全失败方式，例如对测试服务执行只读超时测试。
2. 不要更改或暴露真实API密钥。
3. 触发一次可恢复错误。
4. 确认Revit仍可点击和操作，没有卡死。
5. 确认面板显示错误；如果错误可重试，“重试”按钮应可用。
6. 打开`operations.jsonl`、`agent.log.jsonl`和`session.md`。
7. 确认错误被记录，但没有真实Authorization或API密钥。

### 预期结果

- [ ] 成功工具调用有机器可读JSONL记录。
- [ ] 成功输入和输出在Markdown中可人工阅读。
- [ ] 错误有时间、工具名和错误信息。
- [ ] 敏感字段已遮蔽。
- [ ] 错误不会阻塞Revit。

## 13. 用例07：确认RVT没有被修改或自动保存

1. 测试期间不要执行任何Revit编辑命令。
2. 记录测试开始前RVT文件在文件资源管理器中的“修改日期”。
3. 完成上述会话测试后，再次查看RVT文件“修改日期”。
4. 确认修改日期没有因为AI Area Assistant会话测试而改变。
5. 关闭AI Area Assistant面板。
6. 关闭开发测试副本。
7. 如果Revit询问是否保存，选择“不保存”。
8. 再次检查RVT文件修改日期。

### 预期结果

- [ ] AI Area Assistant没有主动保存RVT。
- [ ] RVT磁盘文件修改日期没有变化。
- [ ] 所有会话成果只存在外部`AI_Area_Assistant_Data`中。

注意：如果测试前模型已经有人工修改，Revit可能仍然询问是否保存。这不代表AI自动保存。判断自动保存应以RVT磁盘文件修改日期和测试操作记录为准。

## 15. 出现问题时怎么做

### 面板一直显示“连接中”

1. 等待满60秒。
2. 不要连续点击“发送”。
3. 记录面板状态和错误文字。
4. 关闭面板并重新打开一次。
5. 仍失败则停止测试，通知开发人员检查Python路径、端口和环境变量。

### 面板显示“连接失败”

1. 点击一次“重试”。
2. 如果仍失败，记录完整错误文字，但不要记录或截图密钥。
3. 不要自行修改防火墙、代理或API地址。

### 找不到`AI_Area_Assistant_Data`

1. 确认已经发送并完成至少一条消息。
2. 向开发人员再次确认解析后的绝对路径。
3. 不要在整台电脑中搜索真实项目名称或密钥。
4. 如果路径仍不存在，用例00判定阻塞。

### 找不到“继续上次会话”或“新建会话”

1. 确认之前已成功创建会话文件。
2. 关闭并重新打开面板一次。
3. 仍然没有选项时，用例00判定阻塞。
4. 报告“面板存在，但Issue #5恢复界面尚未接入”。

### 发现敏感值没有遮蔽

1. 立即停止测试。
2. 不要上传相关文件或截图。
3. 只记录文件名、字段名和发生时间。
4. 通知开发人员按安全缺陷处理。

### 面板意外执行了模型操作

1. 立即停止点击面板。
2. 不保存RVT。
3. 记录发生时间和面板显示内容。
4. 关闭测试副本并选择“不保存”。
5. 将问题标记为阻断合并。
