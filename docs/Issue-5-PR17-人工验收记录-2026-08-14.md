## 详细结果

### 用例 1：基线与显式选择

结果：**通过**。

- PR #17 面板可见“文档安全状态”“验证文档”和会话选择入口；
- 文档验证后由用户明确选择会话；
- 选择前不能发送，激活会话后才恢复发送；
- 未自动执行任何 Revit 模型操作。

### 用例 2：同一 Revit 进程 A → B

结果：**通过**。

- 在同一 Revit 进程中从 A 切换到 B；
- 面板自动进入暂停状态，不依赖用户点击“验证文档”触发暂停；
- “发送”自动禁用；
- B 需要重新验证并由用户明确选择会话；
- B 的会话状态和外部数据路由指向 B，未继续使用 A 的会话。

测试时曾在文档切换的短暂过渡阶段看到旧聊天历史，但复测确认面板会自动暂停且发送资格被撤销；旧历史仅为界面显示，没有作为 B 的消息发送或写入。

### 用例 3：回复途中切换

结果：**通过**。

- 在 A 中发送长回复请求，并在回复完成前切换到 B；
- A 的 `conversation.jsonl` 中保留了切换前已写入的用户请求；
- 该用户请求之后没有新增 assistant 记录；
- 因此，切换后完成的迟到回复未落入 A 的旧会话记录。

人工核对的 JSONL 共三条记录：一组已完成的 user/assistant 测试消息，以及最后一条迟到回复测试的 user 请求。为避免泄露本机信息，本记录不提交该文件及其真实路径。

### 用例 4：撤销失败与显式重试

结果：**通过**。

测试协助过程：在 A 会话处于可发送状态且没有回复生成时，停止端口 8766 上的本地 Agent；随后由测试人员从 A 切换到 B，以可恢复的本地通信中断制造一次真实的 `session.revoke` 失败。确认失败状态后，重新启动同一 PR 构建的 Agent。

实测结果：

- 撤销失败后面板显示“旧会话撤销失败；保持暂停”提示；
- B 没有提前验证或打开会话；
- “发送”“继续所选会话”和“新建会话”均保持禁用；
- Agent 恢复后面板没有自动继续；
- 用户点击一次“验证文档”后才重新执行撤销屏障并验证 B；
- B 的会话选择出现前，“发送”保持禁用。

### 用例 5：RVT 未自动保存

结果：**通过**。

- 测试人员确认 A、B 测试前后的磁盘修改时间分别保持一致；
- 测试过程中没有执行保存、另存为、同步或发布；
- 关闭测试文件时未保存 RVT；
- 新增记录只出现在插件的外部数据目录。
